# references/governance.md — Per-package governance artifacts (helpers, never blockers)

Generated packages carry native Turnstone governance objects **when deployed
on Turnstone** (the engine's own platform): a prompt policy and advisory
judge rules derived from the persona's principles and the risk surface. They
are **helpers**: advisory, operator-visible, and reversible — never silent
blockers, never restrictive by default. Portable-only packages (deployed to
non-Turnstone Agent Skills-compatible runtimes) receive the same advisory
posture as documented guidance, not native objects.

## Why per-package governance

The engine is built on Turnstone's Governance surface (prompt policies,
judge rules, audit). Packages it generates are deployed on Turnstone, so
each package ships with its own governance wiring — the same pattern the
engine uses on itself (`process-engine-context` policy + heuristic rule
`process-engine-authoring`).

## The two artifacts

### 1. Prompt policy (the package's operating stance)

- **Content:** the package's durable principles — its heads-up posture, its
  operator-gate rule, its evidence-naming, its scope — written as the
  package's context for any session that runs on it.
- **Form:** content-only, priority 1, **no tool_gate**. Never restricts
  tools.
- **Deploy:** `POST /v1/api/admin/prompt-policies`.
- **Rollback:** disable or delete the policy.

### 2. Judge rules (the package's risk posture)

- **Content:** advisory heuristic rules on the package's own tool family
  (e.g. tool pattern = the package's skill family), risk=low,
  recommendation=review — so the package's actions surface intent
  verdicts for the operator's awareness.
- **Form:** advisory only. A verdict informs; it never blocks. The operator
  remains the only gate.
- **Deploy:** `POST /v1/api/admin/judge/heuristic-rules`.
- **Rollback:** delete the rule.

## Non-negotiables (the "never silent blockers" rule)

- **No tool_gate on the prompt policy** — a policy that gates tools would
  restrict the package's sessions; that is not the engine's posture.
- **No deny/high-risk judge rule by default** — the default posture is
  low-risk, advisory, review. Anything stronger is an explicit operator
  decision per package.
- **Operator-visible** — both artifacts are documented in the package
  (governance/ section) and surfaced at ship; nothing hidden.
- **Reversible** — disable/delete is the rollback path for both.

## When

Generated by `process-engine-pattern-author` (step 7) at authoring time;
deployed by `process-engine-ship` (step 3) at ship time; verified by
read-back. Reviewed as part of the review gate.
