# Package Manifest Schema

> **Historical / superseded.** This document describes the Process Engine era. Current Method Factory architecture and release state: see [architecture-reset-status.md](architecture-reset-status.md) and [ADR-0012](adr/ADR-0012-persistence-architecture.md).

> The durable state record that connects every pipeline stage. Every package
> generated by Process Engine carries a manifest from intent through deployment.

## Purpose

The manifest is the single canonical record of a package's lifecycle. It
connects the pipeline stages (Collect → Clarify → Objective → Gate → Pattern →
Review → Trial → Ship) and provides the evidence trail the engine promises.

## Schema

```yaml
schema_version: 2

# Identity
package_id: <unique-id>
package_version: <semver>
target_runtime:
  - portable          # portable | turnstone | both

# Evidence & provenance (v2)
engine_version: <Process Engine version>
engine_lineage: <content lineage>
evaluator_version: <schema-bound evaluator version>
assertion_contract:
  total: <assertion count>
  deterministic: <regex/predicate count>
  semantic: <semantic-judge count>
  evidence_path: <bundle-relative assertions path, e.g. evals/runs/<run>/run-a/assertions.jsonl>
semantic_judge:
  model: <judge model alias>
  rubric_hashes: [<sha256>]
  prompt_hash: <sha256>
hashes:
  package: <sha256 of package inputs>
  transcripts: {<case_id>: <sha256>}
provenance:
  executor: <who ran the cases>
  verifier: <who verified the results>
  environment: <model/provider/node snapshot>
  timestamps:
    start: <ISO-8601>
    completion: <ISO-8601>
  baseline: executed | not-executed
  baseline_relation: <preserved comparison or new baseline run>
  engine_version: <Process Engine version>
  persona: <persona name>
  skill: <entry skill name>
  commit: <repo commit SHA>
  created_at: <ISO-8601>

# Assurance tier
assurance_tier:
  selected: lightweight | standard | high-assurance
  basis:
    - risk_domain
    - authority_level
    - reversibility
    - external_side_effects
  operator_override: null | <operator direction>
  escalated_from: null | <previous tier>

# Intent
intent:
  raw: <operator's original words>
  clarified: <post-clarification summary>

# Objective
objective: <what problem is being solved and why it matters>
desired_outcomes:
  - <observable end state 1>
  - <observable end state 2>

# Inputs
inputs:
  - id: SRC-001
    type: skill | domain-context | example | general-input
    source: <URL or "user-provided, source unknown">
    fetched_at: <ISO-8601 or null>
    license: <license if known, or null>
    trust: untrusted        # all external input is untrusted
    disposition: incorporated | excluded
    exclusion_reason: <if excluded, why>

# Artifacts
artifacts:
  - type: persona | skill | template | project | prompt-policy | judge-rule
    name: <artifact name>
    path: <relative path in package>
    status: DRAFT | REVIEW | TRIALED | SHIPPED

# Review
review:
  verdict: PASS | REVISE | REJECT
  findings:
    - id: REV-001
      severity: high | medium | low
      location: <file + section>
      requirement: <which standard/rule>
      evidence: <what was found>
      required_correction: <what must change>
  approved_by: operator
  approved_at: <ISO-8601>

# Trial
trial:
  run_id: <unique run id>
  total_cases: <N>
  passed: <N>
  failed: <N>
  verdict: PASS | FAIL
  evidence_path: <path to run bundle>

# Deployment
deployment:
  deployment_id: <unique id>
  target: turnstone | filesystem | git
  status: PLANNED | APPLYING | VERIFYING | COMPLETE | PARTIAL
  objects:
    - type: project | persona | skill | template | prompt-policy | judge-rule
      id: <created object id>
      preexisting: false
      rollback: delete | restore_previous_content
  rollback_plan: <human-readable rollback description>

```

## When the manifest is created

The manifest is initialized at the **Gate** stage (after intent clarification
and objective formation) and updated at each subsequent stage:

| Stage | Manifest update | Enforced by |
|-------|----------------|-------------|
| Gate | Initialize: package_id, intent, objective, inputs | `process-engine-core` — no manifest, no package |
| Pattern | Add artifacts (DRAFT), desired_outcomes, target_runtime | `process-engine-pattern-author` — reads canonical manifest, appends, passes path+hash |
| Review | Add review verdict + findings + isolation level + operator approval | `process-engine-review` — refuses review without manifest |
| Trial | Add trial run_id + verdict + evidence_path + content hashes | `process-engine-trial` — links exact run bundle |
| Ship | Add deployment objects + status + rollback_plan | `process-engine-ship` — refuses ship unless manifest gates pass |
| Triage | Link defect to package_id / version / deployment / trial | `process-engine-triage` — traceability from feedback to shipped artifact |

## Enforced state contract

- The manifest path + content hash travel with the package between stages.
- A stage that produces artifacts but does not update the manifest has not
  completed its handoff.
- Review refuses a package with no manifest (missing intent/input record).
- Ship refuses unless the manifest shows: artifacts recorded, review verdict
  PASS, trial run linked, rollback defined.
- Missing state is a hard stop, not a convenience gap.

```yaml
schema_version: 2
package_id: pkg-20260731-001

  total: 5
  deterministic: 5
  semantic: 0
  evidence_path: "evals/runs/run-20260731-001/run-a/assertions.jsonl"
hashes:
  package: <sha256>
  transcripts: {}
provenance:
  executor: turnstone-orchestrator
  verifier: hermes-gateway
  environment: "model snapshot"
  timestamps:
    start: "2026-07-31T10:00:00+07:00"
    completion: "2026-07-31T11:30:00+07:00"
  baseline: not-executed
  baseline_relation: null
  engine_version: "1.9.0"
  persona: process-engine
  skill: process-engine-core
  commit: 043a887
  created_at: "2026-08-02T09:00:00+07:00"

intent:
  raw: "I want a skill that writes release notes"
  clarified: "Release notes skill for a GitHub-based project"

desired_outcomes:
  - "Release notes generated from merged PRs since last tag"
  - "Notes follow conventional-changelog format"

inputs:
  - id: SRC-001
    type: general-input
    source: "user-provided, source unknown"
    trust: untrusted
    disposition: incorporated

artifacts:
  - type: skill
    name: release-notes
    path: skills/release-notes/SKILL.md
    status: SHIPPED

review:
  verdict: PASS
  findings: []
  approved_by: operator

trial:
  run_id: run-20260731-001
  total_cases: 5
  passed: 5
  failed: 0
  verdict: PASS

deployment:
  deployment_id: dep-20260731-001
  target: filesystem
  status: COMPLETE
  objects:
    - type: skill
      id: skills/release-notes/
      preexisting: false
      rollback: delete
  rollback_plan: "Delete skills/release-notes/ directory"

```
